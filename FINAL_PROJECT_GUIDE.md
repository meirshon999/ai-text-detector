## Part 1. Project Overview

### Что мы исследуем
Можно ли по одному тексту (ответу на вопрос) определить, кто его написал: **человек** или **ChatGPT**.
Это задача **бинарной классификации**: класс 1 = ChatGPT (positive class), класс 0 = человек.

### Почему это актуально
- ChatGPT и другие LLM пишут связный текст почти бесплатно и за секунды.
- Университетам нужно понимать, где работа студента, а где сгенерированный текст. Платформам и СМИ нужно находить массовый сгенерированный контент.
- Ошибка детектора имеет цену: **ложное обвинение человека** (false positive) вредит реальному студенту. Поэтому нам важна не только точность, но и доля ложных обвинений, и честность выводов.

### Какую проблему решаем
Во многих работах детекторы на HC3 показывают точность около 99%. Мы проверяем, **можно ли этим цифрам доверять**:
1. Не учится ли модель на технических артефактах подготовки данных, а не на стиле автора?
2. Работает ли детектор на теме, которой не было в обучении?

### Цель проекта
Сравнить разные подходы к распознаванию текстов ChatGPT **в одинаковых и честных условиях** (одни и те же данные, одно и то же разбиение, один тест). Затем исследовать смещения датасета и перенос на новые темы и сделать работающее демо, которое честно показывает неопределённость.

### Исследовательские вопросы
- **RQ1.** Какой подход лучше: классическое ML, стилистические признаки, языковая модель без обучения (zero-shot) или дообученный трансформер?
- **RQ2.** Насколько хорошо детекторы работают на теме, которой не было в обучающей выборке?
- **RQ3.** Есть ли в датасете скрытые признаки (артефакты), которые искусственно завышают результат?

### Гипотезы (сформулированы на мидтерме)
- **H1.** Лучший результат даст дообученный трансформер RoBERTa (F1 ≥ 0.98).
- **H2.** На новой теме трансформер теряет как минимум на 5 пунктов F1 меньше, чем классическая модель.
- **H3.** Простое правило по форматированию даёт больше 80% на сырых данных и перестаёт работать после очистки.

Итог проверки гипотез — в [Part 8](#part-8-conclusion).

## Part 2. Dataset

### Что такое HC3
**HC3 (Human ChatGPT Comparison Corpus)** — открытый датасет: Guo et al., 2023, *How Close is ChatGPT to Human Experts?*,
[arXiv:2301.07597](https://arxiv.org/abs/2301.07597). Опубликован на Hugging Face (`Hello-SimpleAI/HC3`), лицензия CC-BY-SA.
Мы используем английскую часть.

**Как устроен:** одна строка = один **вопрос**, к нему список **ответов людей** и список **ответов ChatGPT**.
Ответы людей взяты авторами из существующих открытых наборов вопросов и ответов. Ответы ChatGPT авторы собрали в конце 2022 — начале 2023 года, задавая ChatGPT те же вопросы.

| Домен (тема) | Откуда ответы людей | Вопросов | Ответов людей | Ответов ChatGPT |
|---|---|---:|---:|---:|
| `reddit_eli5` | Reddit «Explain Like I'm Five» | 17 112 | 51 336 | 16 660 |
| `finance` | FiQA (финансовые вопросы) | 3 933 | 3 933 | 4 503 |
| `medicine` | Medical Dialog (ответы врачей) | 1 248 | 1 248 | 1 337 |
| `open_qa` | WikiQA | 1 187 | 1 187 | 3 561 |
| `wiki_csai` | Википедия (понятия CS/AI) | 842 | 842 | 842 |
| **Всего** | | **24 322** | **58 546** | **26 903** |

Наблюдения (ноутбук 01):
- `reddit_eli5` — около 80% всех ответов, и там примерно 3 ответа людей на 1 ответ ChatGPT. Без балансировки модель учила бы в основном Reddit и класс «человек».
- ChatGPT пишет ответы «стандартной» длины (около 100–250 слов), люди — от нескольких слов до тысяч. **Длина сама по себе — сильный сигнал**, поэтому нужен baseline только по длине.

### Как проводилась очистка (cleaning protocol)
Каждый шаг записан в `data/interim/cleaning_protocol.json`:

**Нормализация форматирования (шаг 3)** — одинаковые правила для людей и для ChatGPT. Меняется только способ хранения текста, а не автор:

| Было | Стало | Почему так было в данных |
|---|---|---|
| `word , word` | `word, word` | ответы людей в HC3 токенизированы (пробелы вокруг знаков) |
| `do n't` | `don't` | та же токенизация |
| `end.Next` | `end. Next` | у ChatGPT при сборе потерялись переносы строк |
| `\n`, лишние пробелы | один пробел | разное хранение переносов строк у двух классов |
| `( x )`, `$ 5`, `well - known` | `(x)`, `$5`, `well-known` | токенизация |

**Важно:** без шага 3 модель может учиться на пробелах, а не на стиле. Это наша главная находка, см. [Part 5.1](#51-dataset-bias-and-shortcut-learning).

### Как разделялись данные
- **Баланс классов:** на каждый вопрос ровно 1 ответ человека и 1 ответ ChatGPT (случайный выбор, seed 42). В каждой части 50% / 50%. Поэтому accuracy 50% = случайное угадывание.
- **Разделение по вопросам** (`GroupShuffleSplit`, группа = вопрос): 80% train / 10% validation / 10% test. Оба ответа на один вопрос всегда в одной части. Иначе модель могла бы узнать **тему** вопроса в тесте, потому что уже видела её в обучении.
- **Train** — обучение моделей. **Validation** — выбор гиперпараметров, порогов и ранняя остановка. **Test** — только финальная оценка, один раз.

## Part 3. Machine Learning

Все модели решают одну задачу: получают текст и выдают **P(ChatGPT)** — вероятность того, что текст написал ChatGPT.
Решение: P ≥ 0.5 → ChatGPT. Все модели обучаются на одном train, настраиваются на validation и оцениваются на одном test. У zero-shot детекторов и трансформера «сырой» score сначала калибруется на validation (1-мерная логистическая регрессия, 2 числа). Test при этом не используется.

| # | Модель | Семейство | Обучается на HC3? | F1 на test [95% CI] |
|---|---|---|---|---|
| 0 | Length baseline | sanity check | да (1 признак) | 0.771 [0.761–0.782] |
| 1 | TF-IDF + LogReg | классическое ML | да | 0.989 [0.986–0.992] |
| 2a | Stylometry + LogReg | интерпретируемые признаки | да | 0.889 [0.880–0.898] |
| 2b | Stylometry + Random Forest | интерпретируемые признаки | да | 0.934 [0.927–0.941] |
| 3 | PyTorch bag-of-embeddings | нейросеть с нуля | да | 0.952 [0.946–0.958] |
| 4 | GPT-2 perplexity | zero-shot LLM | нет (только калибровка порога) | 0.958 [0.953–0.964] |
| 5 | Fast-DetectGPT на GPT-2 | zero-shot LLM | нет (только калибровка порога) | 0.957 [0.951–0.962] |
| 6a | DistilRoBERTa, full fine-tuning | трансформер | да (5 000 текстов) | 0.986 [0.982–0.989] |
| 6b | DistilRoBERTa + LoRA | трансформер | да (5 000 текстов) | 0.990 [0.987–0.993] |

### Model 0. Length baseline (логистическая регрессия по длине)
- **Принцип:** модель знает только количество слов: признак log(1 + число слов) → логистическая регрессия.
- **Зачем:** это проверка здравого смысла (sanity check). ChatGPT пишет длиннее людей, поэтому длина сама по себе что-то угадывает. Любой настоящий детектор **обязан** заметно обогнать этот baseline. Иначе он учит только длину.
- **Почему нельзя ограничиться им:** длина легко меняется (попросить ChatGPT «ответь коротко»), а у людей длина очень разная. Его точность далека от полезной: ROC-AUC всего 0.7664, а ложно помечается каждый третий человек (33.1%).
- **Результат:** F1 = 0.771, accuracy 75.2%, ROC-AUC 0.7664. Ложно помечено 33.1% людей: модель просто считает длинные тексты ChatGPT.

### Model 1. TF-IDF + Logistic Regression (классическое ML)
- **Вход:** очищенный текст.
- **Что внутри:**
  1. **TF-IDF** превращает текст в вектор из 100 000 чисел. Каждое число — вес одного слова, пары слов (bigram) или знака препинания. Вес большой, если элемент часто встречается в этом тексте (TF) и редко в других текстах (IDF). `sublinear_tf` — логарифм частоты, чтобы повторы не доминировали.
  2. **Logistic Regression** учит вес каждого элемента: положительный тянет к ChatGPT, отрицательный — к человеку. P(ChatGPT) = sigmoid(сумма весов × значений + bias). Регуляризация L2 с силой 1/C.
- **Настройка на validation:** n-grams (1,1) или (1,2) × C ∈ {1, 4, 16}. Выбрано: unigrams + bigrams, C = 16 (F1 на validation 0.989). Class weights не нужны: классы сбалансированы 50/50.
- **Почему выбрали:** сильный, быстрый, прозрачный baseline. Классика для text classification, видно, какие слова важны.
- **Плюсы:** учится за секунды, работает на CPU, интерпретируем (видно топ-слова).
- **Минусы:** учит конкретные слова, а слова зависят от темы. Поэтому падает на новых темах. Не понимает смысл и порядок слов дальше пар.
- **Что модель выучила** (`figures/tfidf_top_words.png`): к ChatGPT тянут «important to», «, which», «, including», «. it» и «. this» в начале предложения, «help(s)»; к человеку — «i», скобки, «/», «*», «etc», «basically», многоточия и заглушка ссылки «url_0». Это реальные особенности стиля (ChatGPT пишет обобщённо и с оборотами вроде «it is important to»), но часть связана с источником ответов людей (разметка Reddit `*`, ссылки).
- **Результат:** **один из двух лучших на test** (вместе с DistilRoBERTa + LoRA, доверительные интервалы пересекаются): F1 = 0.989 [0.986–0.992], ROC-AUC 0.9993, ложно помечено 0.9% людей, TPR при 1% FPR = 98.8%. На train F1 = 1.000: модель полностью «выучила» обучающие тексты, но validation (0.989) и test совпадают, значит переобучения на тест нет. На новых темах теряет больше, чем zero-shot детекторы (Part 5.2).

### Model 2. Stylometric features + Random Forest / Logistic Regression
- **Вход:** 18 базовых признаков стиля + 2 новых (итого 20), посчитанных из текста (`src/detector/features.py`). Длина текста **специально исключена**: её проверяет baseline.

| Группа | Признаки | Зачем (исследовательский смысл) |
|---|---|---|
| Ритм предложений | средняя длина предложения, **burstiness** (разброс длины предложений) | LLM пишут ровнее, люди «рвано» |
| Словарь | **MATTR** (богатство словаря в окне 50 слов), средняя длина слова, доля длинных слов | Guo et al.: у людей богаче словарь |
| Пунктуация и эмоции | `!`, `?`, `...`, скобки, кавычки, запятые на 100 слов | люди выражают эмоции пунктуацией |
| Связность | коннекторы: «however», «additionally», «overall»… | ChatGPT структурирует ответ связками |
| Позиция автора | «I/my/me», «you», hedges («I think», «maybe»), сленг, сокращения (don't) | люди субъективнее и разговорнее |
| Служебные слова | доля function words («the», «of», «and») | классическая стилометрия |

- **Проверка новых признаков:** мы проверили 2 дополнительных кандидата — **читаемость Flesch** и **долю повторяющихся пар слов**. Правило: оставить, только если F1 на validation растёт хотя бы на 0.002. Итог: **оба признака оставлены**: F1 на validation вырос с 0.921 до 0.931. «Доля повторяющихся пар слов» стала самым важным признаком. Мы проверили, что это не скрытая длина текста: на текстах одной длины (100–300 слов) эффект почти не меняется (Cliff's δ = +0.74 против +0.80 на всех текстах). ChatGPT действительно чаще повторяет словосочетания (формульные обороты).
  Признаки **структуры абзацев** не добавляли сознательно. Переносы строк у ChatGPT в HC3 потеряны при сборе — это артефакт (см. Part 5.1). Такой признак снова «научил» бы модель артефакту.
- **Random Forest:** 300 деревьев решений, каждое голосует. Ловит нелинейные связи признаков. `min_samples_leaf` выбран на validation: 1 (сетка 1 / 3 / 5).
- **Logistic Regression** на стандартизованных признаках: полностью интерпретируемые веса (знак = направление).
- **Плюсы:** каждое решение объяснимо понятными характеристиками текста. Меньше зависит от темы, чем слова.
- **Минусы:** признаки придуманы вручную и грубые. Точность ниже, чем у моделей на словах.
- **Что важнее всего** (`figures/feature_importance_stylometry.png`, permutation importance — насколько падает ROC-AUC, если перемешать признак): 1) доля повторяющихся пар слов (у ChatGPT больше), 2) средняя длина предложения (у ChatGPT длиннее), 3) burstiness — разброс длины предложений (у людей больше), 4) скобки (люди), 5) запятые, 6) «I/my/me» (люди), 7) коннекторы «however/overall…» (ChatGPT), 8) восклицательные знаки. Направление каждого признака — `figures/stylometry_logreg_weights.png`.
- **Результат:** Random Forest: F1 = 0.934 [0.927–0.941], ROC-AUC 0.9826 (на мидтерме было 0.918; рост за счёт двух новых признаков и подбора `min_samples_leaf` на validation). Logistic Regression: F1 = 0.889. Лес идеально запоминает train (F1 1.000), поэтому важно, что параметры выбраны на validation.

### Model 3. Neural Network (PyTorch, bag-of-embeddings)
- **Идея** — как у fastText (Joulin et al., 2017): каждое слово получает обучаемый вектор из 64 чисел (embedding). Векторы слов текста усредняются, дальше 2 полносвязных слоя.
- **Архитектура:** словарь 30 000 слов (встречались ≥ 2 раз в train) → `EmbeddingBag(30 001, 64, mean)` → `Linear(64→64)` → `ReLU` → `Dropout(0.2)` → `Linear(64→1)` → sigmoid. Первые 400 токенов текста.
- **Обучение:** loss = **binary cross-entropy** (`BCEWithLogitsLoss`), optimizer = **Adam** (lr = 0.003), batch = 64, до 10 эпох, **early stopping** по validation loss (patience = 2), сохраняется лучшая эпоха. Seed 42.
- **Почему так:** самая простая настоящая нейросеть для текста, которую мы написали сами с нуля и можем объяснить каждую строку.
- **Обучается ли на самом деле:** да. Train loss падает с каждой эпохой, validation loss сначала падает, потом растёт — классическое **переобучение** (overfitting). Early stopping берёт эпоху с минимальной validation loss (`figures/nn_training_curves.png`). Лучшая эпоха: эпоха 2 из 4 (validation loss 0.172 → **0.142** → 0.144 → 0.178).
- **Плюсы:** учит представления слов сама. Быстрая.
- **Минусы:** не учитывает порядок слов (мешок слов). Маленькая. Уступает TF-IDF с биграммами и пунктуацией.
- **Результат:** F1 = 0.952 [0.946–0.958], ROC-AUC 0.9898; на train F1 0.986. Сильнее всех теряет на новой теме (Part 5.2).

### Model 4. GPT-2 Perplexity (zero-shot)
- **Что такое perplexity:** насколько языковая модель «удивлена» текстом. GPT-2 для каждого следующего токена даёт вероятность. Perplexity = exp(среднее −log P(токена)). **Низкая perplexity = предсказуемый текст.**
- **Почему GPT-2 может оценить предсказуемость:** GPT-2 (Radford et al., 2019, 124M параметров) обучена предсказывать следующий токен на большом корпусе текстов из интернета. Если текст состоит из «самых ожидаемых» слов, она даёт им высокую вероятность.
- **Почему у ChatGPT perplexity ниже:** ChatGPT генерирует текст, выбирая высоковероятные токены, поэтому его текст «гладкий» и типичный. Человек выбирает слова менее предсказуемо: опечатки, сленг, редкие слова, необычные обороты.
- **Реализация:** первые 128 токенов текста, батчами, одна прогонка GPT-2 на текст. Мы проверили, что батчевый расчёт совпадает с поштучным расчётом мидтерма до 10⁻⁵. Порог не обучается на текстах: на validation подбирается только **калибровка** (1-мерная логистическая регрессия: score → P(ChatGPT)). Всего 2 числа.
- **Почему это не универсальный способ:** (1) perplexity зависит от темы и длины текста; (2) простой или шаблонный текст человека тоже предсказуем — **ложные обвинения**; (3) Liang et al. (2023): детекторы чаще ошибаются на текстах людей, для которых английский не родной (их лексика проще); (4) перефразирование, повышенная «температура» генерации или другой генератор меняют perplexity; (5) GPT-2 2019 года, а генераторы новее.
- **Результат:** F1 = 0.958 [0.953–0.964] **без обучения на HC3**, ROC-AUC 0.9897. Медиана perplexity: ChatGPT 10.5, люди 38.9. Граница калибровки: perplexity ≈ 18.0 (ниже → ChatGPT). Ложно помечено 4.7% людей. Главное: почти не теряет качество на незнакомой теме (Part 5.2).

### Model 5. Fast-DetectGPT (zero-shot, дополнительный метод)
- **Идея** (Bao et al., ICLR 2024): сравнить вероятность реального текста с вероятностью альтернативных токенов, которые модель **сама бы сгенерировала** на тех же позициях:
  criterion = (log p(x) − E[log p(x̃)]) / sqrt(Var[log p(x̃)]).
  Текст машины находится «на вершине» распределения модели, и его criterion выше.
- **Реализация:** аналитическая версия, GPT-2 и как модель выборки, и как модель оценки. Считается **из той же прогонки GPT-2**, что и perplexity, без дополнительных затрат.
- **Честное ограничение:** в статье используются модели крупнее (например, GPT-Neo-2.7B). С маленькой GPT-2 мы не воспроизводим их цифры, а проверяем идею метода.
- **Результат:** F1 = 0.957 [0.951–0.962], ROC-AUC 0.9912, TPR при 1% FPR = 87.7% (у perplexity 79.1%): при строгом ограничении ложных обвинений Fast-DetectGPT ловит больше текстов ChatGPT.

### Model 6. DistilRoBERTa: full fine-tuning vs LoRA (трансформер)
- **Что такое трансформер:** нейросеть с механизмом **self-attention**: каждый токен «смотрит» на все остальные токены текста. Поэтому модель учитывает контекст и порядок слов. **RoBERTa** (Liu et al., 2019) — улучшенный BERT, предобученный на большом корпусе. **DistilRoBERTa** — уменьшенная копия RoBERTa-base (6 слоёв вместо 12, 82M параметров вместо 125M), обученная повторять её поведение (**distillation**, как в DistilBERT, Sanh et al., 2019). Она примерно в 2 раза быстрее.
- **Fine-tuning:** берём предобученную модель, добавляем классификационную «голову» и доучиваем на наших текстах. **Full fine-tuning** — меняются все 82M весов.
- **LoRA** (Hu et al., 2022): исходные веса **заморожены**. К матрицам attention (query, value) добавляются маленькие матрицы низкого ранга: W' = W + B·A, где A и B ранга r = 8. Обучаются только A, B и классификационная голова: **0.74M параметров = 0.9%** от модели. Плюсы: меньше памяти, маленький файл (адаптер — несколько МБ), меньше риск «испортить» предобученные знания.
- **Наш вычислительный бюджет (честно):** GPU нет, только CPU ноутбука. Поэтому:
  - DistilRoBERTa вместо RoBERTa-base;
  - обучение на случайной подвыборке **2 500 вопросов train (5 000 текстов)**, 1 эпоха, максимум 256 токенов, batch 16, AdamW (lr 3e-5 для full, 5e-4 для LoRA), linear warmup 6%;
  - оценка — на **полном test** (тот же, что у всех моделей);
  - **калибровка** вероятностей на 1 000 текстах validation (2 числа, как у zero-shot детекторов). Test при этом не используется, в таблице показаны обе версии: «raw 0.5» и откалиброванная.
- **Результат:** LoRA: F1 = 0.990 [0.987–0.993], ROC-AUC 0.9996, обучение 34 мин. Full fine-tuning: F1 = 0.986 [0.982–0.989], ROC-AUC 0.9991, обучение 49 мин. После одной эпохи сырые вероятности сдвинуты к «ChatGPT»: при пороге 0.5 ложно помечено 11.1% людей (F1 0.947). Калибровка на 1 000 текстах validation (Platt scaling, 2 числа, как у zero-shot детекторов) это исправляет: F1 0.990, FPR 1.1%. Ранжирование (ROC-AUC) калибровка не меняет. Полное дообучение (100% весов) дало F1 0.986 после калибровки (raw 0.5: 0.964) за 49 мин против 34 мин у LoRA. Доверительные интервалы пересекаются: LoRA, обучая 0.9% весов, не хуже полного дообучения.

### Почему не Binoculars
**Binoculars** (Hans et al., 2024) сравнивает perplexity текста у двух родственных LLM (в статье Falcon-7B и Falcon-7B-instruct). Две модели по 7B параметров не запустить на CPU ноутбука за разумное время. Замена на пару GPT-2 / DistilGPT-2 не была бы честным воспроизведением метода. Поэтому мы **сознательно не включили** Binoculars и выбрали Fast-DetectGPT: он реализуется на доступной модели.

## Part 4. Evaluation

Positive class = **ChatGPT**. Матрица ошибок (confusion matrix):

| | Предсказано: человек | Предсказано: ChatGPT |
|---|---|---|
| **На самом деле человек** | TN (верно) | **FP — ложное обвинение человека** |
| **На самом деле ChatGPT** | FN — пропущенный ChatGPT | TP (верно) |

| Метрика | Формула | Что значит | Зачем нам |
|---|---|---|---|
| **Accuracy** | (TP+TN) / все | доля верных ответов | понятна всем; на сбалансированном тесте 50% = случайность |
| **Precision** | TP / (TP+FP) | из текстов, помеченных «ChatGPT», сколько правда ChatGPT | высокая precision = мало ложных обвинений среди помеченных |
| **Recall (TPR)** | TP / (TP+FN) | какую долю текстов ChatGPT нашли | высокий recall = мало пропусков |
| **F1** | 2·P·R / (P+R) | баланс precision и recall | главная метрика сравнения |
| **ROC-AUC** | площадь под ROC-кривой | вероятность, что случайный текст ChatGPT получит score выше, чем случайный текст человека | качество ранжирования **без выбора порога** |
| **FPR** | FP / (FP+TN) | доля людей, ложно помеченных как ChatGPT | **этика:** цена ошибки для человека |
| **TPR @ 1% FPR** | recall при пороге, где ложно обвинены ≤ 1% людей | сколько ChatGPT поймаем, если почти не обвиняем людей | реальный сценарий: университет может позволить себе очень мало ложных обвинений |

**Почему accuracy недостаточно:** (1) при несбалансированных данных (например, 95% людей) модель «всегда человек» имеет 95% accuracy и бесполезна; (2) accuracy не показывает, **какие** ошибки: ложное обвинение человека хуже пропуска ChatGPT; (3) accuracy зависит от выбранного порога, а ROC-AUC — нет.

**95% доверительные интервалы (bootstrap):** 1 000 раз берём случайную выборку **вопросов** с возвращением (оба ответа на вопрос вместе, они не независимы) и пересчитываем метрику. 2.5-й и 97.5-й процентили = 95% CI. Если интервалы двух моделей не пересекаются, разница надёжна. Если пересекаются, разница может быть случайной.

**Одинаковые условия для всех моделей:** один test (4 380 текстов), один порог (0.5), одна метрика. На мидтерме GPT-2 оценивали на подвыборке 800 текстов. Теперь все модели оценены на полном test.

## Part 5. Experiments

### 5.1 Dataset bias and shortcut learning

**1. Как выглядели исходные данные** (реальные тексты из test):

| | Сырой текст HC3 | После нашей очистки |
|---|---|---|
| Человек (Reddit) | `Basic humanity . Extending kindness to those who do n't necessarily deserve it is a part of that . It 's also …` | `Basic humanity. Extending kindness to those who don't necessarily deserve it is a part of that. It's also …` |
| ChatGPT (Reddit) | `… prevents the fire from continuing to burn.Hydrogen and oxygen …` | `… prevents the fire from continuing to burn. Hydrogen and oxygen …` |

**2. Почему так получилось.** Ответы людей HC3 взяты из старых NLP-датасетов (ELI5, WikiQA, FiQA…). Их когда-то обработали **токенизатором**, который отделяет знаки препинания и сокращения пробелами. Ответы ChatGPT авторы HC3 собрали сами через веб-интерфейс. При сохранении потерялись переносы строк, и предложения слиплись («burn.Hydrogen»). Это **свойство сбора данных, а не авторов**.

**3. Насколько это массово** (`figures/bias_artifacts_before_after.png`, все 79 304 ответа после шагов 1–5):

| Артефакт | Люди, сырой текст | ChatGPT, сырой текст | Люди / ChatGPT после очистки |
|---|---:|---:|---:|
| Пробел перед знаком («word , word») | 87.9% | 0.3% | 0.0% / 0.0% |
| Разделённые сокращения («do n't») | 33.8% | 0.0% | 0.0% / 0.0% |
| Нет пробела после точки («end.Next») | 1.4% | 20.1% | 0.3% / 0.0% |
| Перенос строки внутри ответа | 1.1% | 29.2% | 0.0% / 0.0% |

**4. Почему простой классификатор получает подозрительно высокую точность.** Правило в одну строку «если перед знаком препинания есть пробел → человек, иначе ChatGPT»:

| Данные | Сырой текст | После очистки |
|---|---:|---:|
| Все ответы HC3 (⅔ — люди) | **91.8%** | 33.1% |
| Наш сбалансированный test (50/50) | **85.8%** | 50.0% |

После очистки пробелов нет ни у кого, и правило на всё отвечает «ChatGPT». Поэтому на всех ответах оно верно только для трети (ответов ChatGPT), а на сбалансированном тесте — ровно 50%, как монетка. Правило не знает ничего о языке, но «распознаёт» авторов на 92%. Любая модель, которая видит пробелы, может выучить то же самое.

**5. Стресс-тест: опасен ли этот shortcut на практике?** (`figures/bias_shortcut_stress_test.png`, `bias_shortcut_false_positives.png`)
Обучаем модель на **сырых** текстах и проверяем на **очищенных**, то есть на нормальном человеческом тексте без артефакта. Две модели:
- **символьные n-граммы (1–3 символа)** — видят пробелы, как токенизаторы трансформеров;
- **наш словесный TF-IDF** — делит текст на слова и знаки, пробелы не видит.

| Модель | Обучение → тест | Accuracy | Люди ложно помечены (FPR) |
|---|---|---:|---:|
| Символьные n-граммы | сырой → сырой | 98.8% | 1.2% |
| Символьные n-граммы | **сырой → чистый** | **91.9%** | **15.0%** |
| Символьные n-граммы | чистый → чистый | 97.7% | 2.0% |
| Словесный TF-IDF | сырой → сырой | 98.7% | 1.0% |
| Словесный TF-IDF | сырой → чистый | 98.4% | 1.4% |
| Словесный TF-IDF | чистый → чистый | 98.6% | 1.1% |

**Вывод:** модель, которая видит пробелы и обучена на сырых данных, на бенчмарке выглядит отлично (98.8%). На нормальном тексте людей доля ложных обвинений вырастает с 1.2% до **15.0%**: человек, который ставит пробелы правильно, «похож на ChatGPT». Словесный TF-IDF почти не пострадал, потому что не видит пробелов. Значит, **опасность shortcut зависит от представления текста**. Трансформеры (RoBERTa, GPT-2) кодируют пробелы, поэтому очистка обязательна до их обучения и до вычисления perplexity.

**6. Остаточные артефакты, которые мы тоже проверили:**
- **Заглушки ссылок `URL_0`:** в HC3 ссылки в ответах людей заменены на `URL_0`. Встречаются в 9.1% ответов людей и 0.1% ответов ChatGPT (train). Ablation: удалили заглушки из train и test, F1 TF-IDF (C = 4) 0.986 → 0.987, на Reddit 0.990 → 0.990. **Модель на них не опирается.**
- **Шаблоны врачей (Medicine):** около половины ответов людей в Medicine содержат фразы платформ («Thanks for the query», «HCM», «iCliniq», «Wish you good health»). Отсюда F1 = 1.000 у TF-IDF на медицинском тесте. Это **эффект источника**, а не «человеческий стиль вообще». Такую модель нельзя переносить на медицинские тексты из других источников.
- **Разметка Reddit** (`*`, `[текст](URL_0)`) — реальная привычка людей на Reddit, но тоже признак источника.

**7. Выводы для реальных AI-детекторов:** (1) перед обучением **проверять данные на артефакты сбора**: правило в одну строку — дешёвый, но сильный тест; (2) проверять модель в **стресс-тесте** без артефакта; (3) учитывать, что shortcut опасен для моделей, которые «видят» нужную деталь (пробелы, переносы, разметку); (4) тестировать на данных из **других источников** и всегда сообщать **FPR**. Так ведёт себя shortcut learning в целом (Geirhos et al., 2020): модель решает задачу «короткой дорогой», которая не переносится в реальный мир.

### 5.2 Cross-domain evaluation (generalization)

**Протокол (leave-one-domain-out):** для каждой из 5 тем обучаем модель на train **четырёх других** тем (validation тоже без этой темы) и проверяем на test **этой** темы. Для сравнения берём модель, обученную на всех темах, **на тех же самых тестовых текстах**. Разница — только в том, видела ли модель тему. Zero-shot детекторы ничему не учатся. У них на 4 темах подбирается только калибровка порога.

**Что видно:**
1. **Все обучаемые модели теряют качество на новой теме.** TF-IDF: средняя потеря F1 0.069, худшая тема — 0.840 (Open QA); на Reddit F1 0.992 → 0.866. Нейросеть теряет больше всех: в среднем 0.076, на Reddit 0.955 → 0.751.
2. **Zero-shot детекторы почти ничего не теряют:** GPT-2 perplexity -0.001, Fast-DetectGPT 0.002. Они не учат слова темы, а измеряют предсказуемость текста.
3. **Рейтинг переворачивается.** На знакомых темах лучший TF-IDF (F1 0.989), а на незнакомых в среднем лучше GPT-2 perplexity (0.947 против 0.911 у TF-IDF).

**Почему падает качество:** **domain shift**. Обучаемые модели частично учат слова темы и привычки источника (Reddit, врачи, финансовый форум), а не только стиль ИИ. В новой теме этих подсказок нет.

- **Главный риск для нашего проекта — не переобучение на train, а переобучение на датасет** (shortcut и domain shift, Part 5.1–5.2).

`figures/f1_comparison.png`, `accuracy_comparison.png`, `roc_curves.png`, `confusion_matrices.png`.

**Что видно:**
1. **DistilRoBERTa + LoRA** и **TF-IDF + LogReg** — лучшие (F1 0.990 и 0.989); их 95% CI пересекаются, значит разница не значима.
2. **Zero-shot GPT-2 без обучения** — около 0.96: всего на ~3 пункта ниже, но ложно помечает больше людей (4.7%).
3. При ограничении «не более 1% ложных обвинений» Fast-DetectGPT ловит 87.7% текстов ChatGPT, а perplexity — 79.1%.
4. Наша нейросеть (0.952) уступает TF-IDF: усреднение векторов слов теряет порядок слов и пунктуацию.
5. Стилометрия (0.934) слабее, зато каждое решение объяснимо.
6. Все модели намного лучше baseline по длине (0.771).
7. **Урок калибровки:** тот же трансформер при пороге 0.5 ложно помечает 11.1% людей, после калибровки — 1.1%. Поэтому одного F1 или accuracy недостаточно.

### 5.5 Error analysis

**По темам (F1 на test, модели обучены на всех темах):** TF-IDF: Finance 0.992, Medicine 1.000, Open QA 0.951, Reddit 0.992, Wikipedia 0.968. Самая трудная тема для всех — Open QA. Medicine почти идеальна из-за шаблонов врачей (Part 5.1).

**По длине текста** (`figures/errors_by_length.png`, отдельно для каждого класса):
- В HC3 ChatGPT почти не пишет коротких ответов: среди 777 текстов теста короче 50 слов только **19** ответов ChatGPT. Их детекторы часто пропускают: GPT-2 perplexity — 12 of 19 (63%), TF-IDF — 2 of 19 (11%). Выборка маленькая, поэтому это сигнал, а не точная оценка.
- Длинные ответы людей помечаются чаще коротких (TF-IDF: 2.4% для 200–399 слов против 0.3% до 50 слов). Длинный структурированный ответ человека больше похож на ChatGPT.

**Примеры ошибок** лучшей модели сохранены в `results.json → error_examples`. Демо показывает один такой случай: «Hard case: human text that TF-IDF flags as ChatGPT».

## Part 7. Limitations

Честно озвучиваем комиссии:

1. **Ограниченность датасета.** Один генератор (ChatGPT, конец 2022 — начало 2023), только английский язык, только формат «вопрос → ответ», 5 тем. Ответы людей собраны из старых форумов и датасетов (Reddit, FiQA, MedDialog, WikiQA, Википедия). У каждого источника свои привычки оформления (ссылки `URL_0`, приветствия врачей). Модель частично учит **источник**, а не только «человеческий стиль».
2. **Изменение поведения LLM.** GPT-4, Claude, Gemini, Llama и новые версии ChatGPT пишут иначе, чем ChatGPT 2023 года. На текстах новых моделей мы **не тестировали**, поэтому не можем утверждать, что детектор их распознаёт.
3. **Перефразирование AI-текста.** Krishna et al. (2023) показали, что перефразирование сильно снижает качество детекторов. Мы **не проверяли** устойчивость к перефразированию — это ограничение и задача на будущее.
4. **Смешанный текст.** Если человек отредактировал ответ ChatGPT или вставил в свой текст несколько сгенерированных предложений, один ответ «human/ChatGPT» для всего текста некорректен. Наши детекторы работают с целым текстом и таких случаев не видели.
5. **Domain shift.** На новой теме качество падает у всех моделей (см. Part 5.2). Реальные тексты (эссе, письма, код-ревью) отличаются от ответов в HC3 ещё сильнее.
6. **False positives.** Даже лучший детектор ложно помечает часть людей как ChatGPT (1.1% у лучшего, до 10.4% у стилометрии). Длинные структурированные ответы людей помечаются чаще. Liang et al. (2023) показали предвзятость детекторов против людей, для которых английский не родной. Поэтому **детектор нельзя использовать как единственное доказательство** против человека.
7. **Вычислительные ограничения.** Трансформер дообучен на подвыборке (5 000 текстов, 1 эпоха) на CPU. С полной выборкой и GPU результат, вероятно, был бы выше — это предположение, мы его не проверяли. Перенос на новые темы для трансформера мы не измеряли (5 дополнительных дообучений на CPU не помещались в сроки).
8. **Усечение текста.** GPT-2 видит первые 128 токенов, DistilRoBERTa — первые 256 токенов. Конец длинного текста эти модели не учитывают.
9. **Статистическая неопределённость.** Для маленьких тем (Wikipedia CS/AI: 154 текста в test) доверительные интервалы широкие. Разницу в 1–2 пункта F1 на таких темах нельзя считать надёжной.

## Part 8. Conclusion

### Ответы на исследовательские вопросы

**RQ1. Какой подход лучше?**
На знакомых темах лучшие — **DistilRoBERTa + LoRA** (F1 0.990 [0.987–0.993], после калибровки на validation) и **TF-IDF + LogReg** (F1 0.989 [0.986–0.992]). Их доверительные интервалы пересекаются, поэтому мы **не утверждаем**, что одна лучше другой. Дальше идут zero-shot детекторы GPT-2 (≈ 0.96 **без обучения**), наша нейросеть (0.952), стилометрия (0.934) и baseline по длине (0.771).
Нюанс: трансформер лучше всех **ранжирует** тексты (ROC-AUC 0.9996). Но без калибровки при пороге 0.5 он ложно помечает **11.1%** людей, а после калибровки — 1.1%. Полное дообучение (100% весов) дало F1 0.986 после калибровки (raw 0.5: 0.964) за 49 мин против 34 мин у LoRA. Доверительные интервалы пересекаются: LoRA, обучая 0.9% весов, не хуже полного дообучения.

**RQ2. Работает ли детектор на незнакомой теме?**
Обучаемые модели теряют качество: TF-IDF в среднем −0.069 F1, наша нейросеть до −0.205 на Reddit. Zero-shot детекторы GPT-2 почти ничего не теряют и на незнакомых темах оказываются **лучше** TF-IDF (средний F1 0.947 против 0.911). Трансформер проверен на одной теме (Reddit, обучение без неё): F1 0.995 → 0.980, у TF-IDF на той же теме 0.992 → 0.866.

**RQ3. Есть ли скрытые артефакты?**
Да. Форматирование одно даёт 91.8% accuracy (правило «пробел перед пунктуацией → человек»). Модель, которая видит пробелы и обучена на сырых данных, на чистом человеческом тексте ложно обвиняет **15.0%** людей вместо 1.2%. Остаточные артефакты проверены: заглушки `URL_0` на результат почти не влияют, а шаблоны врачей в Medicine — эффект источника.

### Гипотезы

| Гипотеза | Итог |
|---|---|
| **H1.** RoBERTa — лучший детектор, F1 ≥ 0.98 | **Частично подтверждена.** Дообученный трансформер (DistilRoBERTa вместо RoBERTa-base) достиг F1 0.990 ≥ 0.98 и лучшего ROC-AUC (0.9996), но статистически не отличается от TF-IDF (0.989) и без калибровки порога даёт F1 всего 0.947. |
| **H2.** На новой теме трансформер теряет на ≥ 5 пунктов F1 меньше классической модели | **Подтверждена на одной теме (Reddit):** трансформер потерял 0.015 F1, TF-IDF — 0.126 (разница 0.111 ≥ 0.05). На остальных 4 темах для трансформера не проверено. |
| **H3.** Правило по форматированию > 80% на сырых данных и не работает после очистки | **Подтверждена:** 91.8% → 33.1% (на сбалансированном test 85.8% → 50.0%) |

### Научные выводы
1. **Высокий F1 на бенчмарке ≠ надёжный детектор.** 0.99 на HC3 получено на тех же источниках, той же теме и том же генераторе. Shortcut и domain shift это скрывают.
2. **Аудит данных обязателен.** Правило в одну строку нашло shortcut, а стресс-тест показал реальный вред: в 12 раз больше ложных обвинений.
3. **Точность и обобщение — разные свойства.** TF-IDF, одна из двух лучших моделей на знакомых темах, сильно теряет на новых. Zero-shot методы и трансформер (проверен на Reddit) устойчивее к смене темы.
4. **Калибровка и FPR важны не меньше F1.** Один и тот же трансформер ложно обвиняет 11.1% или 1.1% людей в зависимости от порога.
5. **LoRA эффективна:** при обучении 0.9% параметров на 5 000 текстах (1/7 train) за 34 минуты на CPU трансформер вышел на уровень лучшей классической модели, а на незнакомой теме (Reddit) потерял в 8 раз меньше неё.

### Практические выводы
- Детектор — **подсказка для человека, а не доказательство**. Показывать вероятность, зону неопределённости и известную долю ложных срабатываний (так сделано в демо).
- Для другой темы или источника нужна проверка заново: перенос не гарантирован.
- Перед реальным применением порог нужно выбирать под допустимую долю ложных обвинений (например, 1%), а не по умолчанию 0.5.
- Идея на будущее, **не проверенная нами**: объединить модель на словах (точность на знакомой теме) и zero-shot score (устойчивость к теме).

### Что сделали бы дальше
Тексты новых генераторов (GPT-4, Claude, Llama), перефразированные и смешанные тексты, RoBERTa-base на GPU на полном train с проверкой на всех незнакомых темах, Binoculars с моделями 7B, другие языки (русский, казахский).

## Appendix

### A. Глоссарий (простыми словами)

| Термин | Простыми словами |
|---|---|
| Classification / detection | Классификация: выбрать класс из заданных (человек / ChatGPT). Detection в нашей работе — та же бинарная классификация, но в реальном мире «ChatGPT» — это любые LLM, и детектор должен находить и незнакомые ему генераторы |
| Data leakage | «Подсмотреть ответ»: в обучение попала информация из теста, и оценка получается завышенной |
| Shortcut learning | Модель решает задачу «короткой дорогой»: по случайному признаку (пробелы), а не по сути (стиль) |
| Dataset bias / artifact | Систематическое отличие классов, которое возникло из-за сбора данных, а не из-за самой задачи |
| Domain shift | Тексты в применении отличаются от текстов в обучении (другая тема, жанр, генератор) |
| Overfitting | Модель запоминает обучающие примеры вместо общих правил: на train отлично, на новых данных хуже |
| Early stopping | Остановить обучение, когда ошибка на validation перестала падать |
| TF-IDF | Вес слова: часто в этом тексте и редко в остальных → большой вес |
| Logistic regression | Линейная модель: взвешенная сумма признаков → sigmoid → вероятность |
| Random forest | Много решающих деревьев на случайных подвыборках, итог — голосование |
| Embedding | Вектор чисел, который представляет слово; похожие слова получают похожие векторы |
| Transformer / self-attention | Архитектура, где каждый токен смотрит на все остальные и взвешивает их важность |
| Fine-tuning | Доучить предобученную модель на своей задаче |
| LoRA | Дообучение маленьких добавочных матриц вместо всех весов модели |
| Perplexity | Насколько модель «удивлена» текстом; низкая = текст предсказуемый |
| Zero-shot | Метод без обучения на наших данных (только калибровка порога) |
| Calibration (Platt scaling) | Перевод «сырого» score в вероятность с помощью 1-мерной логистической регрессии |
| Bootstrap CI | Доверительный интервал из многократных случайных перевыборок теста |
| LODO | Leave-one-domain-out: обучить на 4 темах, проверить на 5-й |
